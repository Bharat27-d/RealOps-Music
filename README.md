## 2. YouTube Hardening & OAuth First-Run Flow

YouTube aggressively challenges datacenter IP ranges with `"Sign in to confirm you're not a bot"` or HTTP 403/429 errors. To mitigate this, `youtube-source` utilizes YouTube OAuth2 device authorization.

> [!CAUTION]
> **Use a THROWAWAY Google account ONLY.**
> Never use your personal Google account. If YouTube flags automated streaming sessions, you do not want your primary personal account suspended.

### Step 1: Initial OAuth Device Authorization Flow
1. In your `.env` or `application.yml`, ensure `plugins.youtube.oauth.enabled: true` and leave `refreshToken` blank.
2. Start the Lavalink container:
   ```bash
   docker compose up -d lavalink
   ```
3. Watch the container logs:
   ```bash
   docker compose logs -f lavalink
   ```
4. Look for the prompt generated by `dev.lavalink.youtube.http.YoutubeOauth2Handler`:
   ```
   [YoutubeOauth2Handler] Go to https://www.google.com/device and enter code XXXX-XXXX
   ```
5. Open `https://www.google.com/device` in your browser while signed into your **throwaway** Google account.
6. Enter the displayed code and authorize the session.
7. Upon successful login, Lavalink will print your refresh token to the log output:
   ```
   [YoutubeOauth2Handler] Your refresh token is: 1//04xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
   ```

### Step 2: Persisting the Token
Copy the token string and set it in your `.env`:
```dotenv
YOUTUBE_OAUTH_REFRESH_TOKEN=1//04xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```
On subsequent boots, Lavalink reads this environment variable and skips the interactive login prompt automatically.

### Step 3: Runtime Token Rotation (Zero Downtime)
When rotating OAuth refresh tokens, Proof-of-Origin (`poToken`), or `visitorData`, do not restart the container (which would drop active guild players). Instead, call the REST endpoint via our helper script:

```bash
# Using the helper script:
./infra/scripts/update-youtube-tokens.sh \
  http://127.0.0.1:2333 \
  youshallnotpass \
  "YOUR_PO_TOKEN" \
  "YOUR_VISITOR_DATA" \
  "NEW_REFRESH_TOKEN"
```

Or directly via `curl`:
```bash
curl -X POST http://127.0.0.1:2333/youtube \
  -H "Authorization: youshallnotpass" \
  -H "Content-Type: application/json" \
  -d '{
    "refreshToken": "NEW_REFRESH_TOKEN",
    "skipInitialization": true,
    "poToken": "OPTIONAL_PO_TOKEN",
    "visitorData": "OPTIONAL_VISITOR_DATA"
  }'
```
Lavalink immediately responds with `HTTP 204 No Content` and applies the updated tokens without interrupting audio playback.

## 3. Remote Cipher Server (Documented per Specification)

The `youtube-source` plugin supports an optional remote decipher server:
```yaml
plugins:
  youtube:
    customCipherServerUrl: "http://your-cipher-service:8080"
```

### Trade-offs:
- **Trust**: Outgoing YouTube player script URLs and extraction data are transmitted through the cipher server. A compromised cipher server could inject altered bytecode or monitor queries.
- **Availability**: If the remote cipher service suffers downtime, latency spikes, or upstream IP bans, **all** YouTube stream decryptions will fail simultaneously across your entire bot fleet.
- **Recommendation**: Keep local cipher extraction enabled with explicitly pinned plugin versions (`1.18.2`). Only deploy a self-hosted decipher server if YouTube changes player encryption faster than upstream plugin patches can be applied.

## 4. LavaSrc & Spotify Playback Mechanism

> [!IMPORTANT]
> Spotify links **only supply track metadata** (track title, artist names, duration, and ISRC code). Spotify does not permit headless raw audio streaming.

LavaSrc resolves Spotify tracks to playable audio via the following ordered fallback chain in `application.yml`:
1. `ytsearch:"%ISRC%"` — Queries YouTube using the track's international standard recording code for an exact match.
2. `ytmsearch:%QUERY%` — Falls back to YouTube Music search by `artist - track title`.
3. `ytsearch:%QUERY%` — Falls back to standard YouTube video search.
4. `scsearch:%QUERY%` — Falls back to SoundCloud search if YouTube is blocked or returns no audio.

If all fallback sources fail, track resolution fails.

## 5. Datacenter Mitigation Option 1: Hetzner IPv6 Route Planner

Hetzner dedicates an entire `/64` IPv6 subnet to each dedicated and cloud server (18.4 quintillion addresses). Lavalink's `RotatingNanoSwitch` rotates the local outgoing source address per nanosecond offset, cycling away from individual rate-limited IP addresses.

### Host Setup Script
Run the automated configuration script on your Hetzner host:
```bash
sudo ./infra/scripts/setup-ipv6.sh 2a01:4f8:xxxx:xxxx::/64
```

What this script configures:
1. `net.ipv6.ip_nonlocal_bind=1` in sysctl, allowing sockets to bind to any unassigned IP inside the `/64`.
2. `ip -6 route add local 2a01:4f8:xxxx:xxxx::/64 dev lo`, routing the subnet directly to loopback.
3. Tests outgoing connectivity using 3 distinct generated IPv6 addresses.

### Docker Networking Requirement
Standard Docker bridge networks do not automatically inherit host IPv6 routing tables. For Lavalink to bind to host IPv6 addresses:
- **Option A (Recommended for Hetzner)**: Run Lavalink with host networking:
  ```yaml
  network_mode: host
  ```
- **Option B**: Enable native IPv6 on the Docker daemon (`/etc/docker/daemon.json`) with an assigned sub-prefix.

### Honest Limitations
> [!WARNING]
> IPv6 rotation is a **mitigation**, not a guarantee:
> - YouTube monitors entire `/64` subnets and Autonomous System Numbers (Hetzner AS24940).
> - Under sustained heavy load, YouTube frequently flags the entire datacenter `/64` block, resulting in HTTP 429 or bot-check challenges across all rotated addresses after days or weeks.
> - IPv6 rotation only affects YouTube traffic; it does not affect Spotify metadata or Discord voice traffic.

## 6. Datacenter Mitigation Option 2: Residential Lavalink Node

The definitive solution to datacenter IP blocking is deploying a secondary Lavalink node (Node B) on a home residential internet connection (Raspberry Pi, spare mini PC, or desktop).

### Setup Guide (Tailscale / WireGuard Only)

#### 1. Security & Network Isolation
- **NEVER expose port 2333 to the public internet on your home router.** Do not configure port forwarding.
- Connect both the Hetzner server and your residential host to a private mesh VPN such as [Tailscale](https://tailscale.com/).
- On the residential host, inspect its assigned Tailscale IP:
  ```bash
  tailscale ip -4
  # Example output: 100.64.0.2
  ```

#### 2. Firewall Rule (UFW)
Ensure only the Tailscale interface can communicate with Lavalink:
```bash
# Allow Tailscale interface traffic
sudo ufw allow in on tailscale0 to any port 2333 proto tcp
# Block all external interfaces
sudo ufw deny 2333/tcp
```

#### 3. Run Residential Container
Navigate to `infra/residential/` and create `.env.residential`:
```dotenv
TAILSCALE_IP=100.64.0.2
LAVALINK_SERVER_PASSWORD=your_super_secret_high_entropy_password
LAVALINK_JVM_OPTS=-Xmx1536M -XX:+UseG1GC
SPOTIFY_CLIENT_ID=...
SPOTIFY_CLIENT_SECRET=...
```
Start the service:
```bash
docker compose -f infra/residential/docker-compose.yml up -d
```

#### 4. Test Connectivity from Hetzner Node
From the Hetzner terminal, verify private communication over the VPN:
```bash
curl -v http://100.64.0.2:2333/version -H "Authorization: your_super_secret_high_entropy_password"
```
Expected response:
```
4.2.2
```

### Bandwidth Estimation for Residential Connections
Audio streaming from Lavalink to Discord voice channels uses the Opus codec (64 kbps to 128 kbps) wrapped in WebSocket frames with protocol overhead (~128–160 kbps per stream = ~20 KB/sec).

| Concurrent Streams | Required Upload Bandwidth | Monthly Data at 8 hrs/day |
|---|---|---|
| **1 Stream** | ~160 kbps (0.16 Mbps) | ~17 GB |
| **5 Streams** | ~800 kbps (0.80 Mbps) | ~86 GB |
| **10 Streams** | ~1.6 Mbps | ~172 GB |
| **20 Streams** | ~3.2 Mbps | ~345 GB |
| **50 Streams** | ~8.0 Mbps | ~860 GB |

A modest residential fiber or broadband connection (20–100+ Mbps upload) can easily support dozens of concurrent audio streams without impacting home internet usage.

## 7. Node Health Verification & Upgrades

### Health Verification Endpoints
To verify the health and metrics of any Lavalink node:

```bash
# Check version:
curl -s http://127.0.0.1:2333/version -H "Authorization: youshallnotpass"

# Check node operational information & loaded plugins:
curl -s http://127.0.0.1:2333/v4/info -H "Authorization: youshallnotpass" | jq .

# Check memory, CPU, and connected player statistics:
curl -s http://127.0.0.1:2333/v4/stats -H "Authorization: youshallnotpass" | jq .
```

### Safe Plugin Upgrade Procedure
1. Verify the latest release on [youtube-source GitHub Releases](https://github.com/lavalink-devs/youtube-source/releases) and [LavaSrc GitHub Releases](https://github.com/topi314/LavaSrc/releases).
2. Update the version string in `infra/primary/application.yml` and `infra/residential/application.yml`:
   ```yaml
   lavalink:
     plugins:
       - dependency: "dev.lavalink.youtube:youtube-plugin:NEW_VERSION"
   ```
3. Restart the container during a maintenance window:
   ```bash
   docker compose restart lavalink
   ```
4. Confirm plugin loading in the startup log:
   ```bash
   docker compose logs lavalink | grep -i "Loaded plugin"
   ```

## 10. Production Troubleshooting Matrix

| Issue / Error Pattern | Root Cause | Production Resolution |
|---|---|---|
| **"Sign in to confirm you're not a bot"** (HTTP 403) | Datacenter IP flagged by YouTube's anti-bot heuristic. | 1. Ensure `youtube-source` OAuth is completed using a throwaway account.<br>2. Rotate `poToken` and `visitorData` using `./infra/scripts/update-youtube-tokens.sh`.<br>3. Failover automatically occurs to the residential node (Node B) if configured. |
| **HTTP 429 Too Many Requests** | YouTube rate limit reached on datacenter IP or `/64` block. | 1. Circuit breaker automatically opens and moves SoundCloud to the front of the fallback order.<br>2. Run `./infra/scripts/setup-ipv6.sh` on Hetzner to verify IPv6 rotation is healthy.<br>3. Deploy or verify the residential node connection. |
| **SABR / No playable stream found** | YouTube served a SABR-only response that broke format parsing in legacy plugins. | 1. Ensure `youtube-source` is pinned to `1.18.2` or higher (includes format 18 legacy fallback).<br>2. The bot's recovery layer automatically falls back to YouTube Music or SoundCloud mirror. |
| **Spotify: Track not found or playback error** | Spotify only provides metadata; fallback search returned no playable match. | 1. Ensure `SPOTIFY_CLIENT_ID` and `SPOTIFY_CLIENT_SECRET` are valid.<br>2. Verify LavaSrc provider chain in `application.yml`: `"ytsearch:\"%ISRC%\""`, `"ytmsearch:%QUERY%"`, `"ytsearch:%QUERY%"`, `"scsearch:%QUERY%"`.<br>3. Check if track is region-locked or has special characters. |
| **Discord DAVE / E2EE Voice Connection Problems** | Discord rolled out DAVE E2EE voice protocol; client or server lacks DAVE libraries. | 1. Verify Lavalink image is pinned to `4.2.2` (includes native `libdave` v0.1.3).<br>2. Ensure `channelId` is transmitted in voice state updates (handled natively by Shoukaku v4).<br>3. If running Alpine container, ensure glibc/libstdc++ compat is present (included in default `ghcr.io/lavalink-devs/lavalink:4.2.2`). |
| **Voice WebSocket closed unexpectedly (Code 4014 / 4006)** | Bot was moved across channels or voice region updated by Discord. | Shoukaku handles session resumption automatically. If bot was kicked or channel deleted, `PlayerManager` cleanly tears down listeners. |
